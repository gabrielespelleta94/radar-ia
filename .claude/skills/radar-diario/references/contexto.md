# Contexto del usuario (plantilla: cámbialo por el tuyo)

Este fichero es lo único que hay que tocar para que el radar puntúe según tu trabajo. Cuanto más concreto, mejores quick wins. No pongas datos de cliente, cifras reales ni secretos: el texto se usa para escribir y puede acabar en el dashboard.

ROL: (ejemplo) Jefa de proyecto de datos en una consultora. Semana: 40 % gestión y coordinación, 30 % desarrollo y validación, 20 % documentación y reuniones, 10 % preventa.

PROYECTOS (nombre corto, en qué consiste, dolor principal):
- Plataforma de planificación: migración de hojas de cálculo a una app de datos con reglas de negocio. Dolor: validar lo que construye un agente de código.
- Informe financiero: cuenta de resultados sobre un modelo semántico. Fase inicial. Dolor: documentar el modelo para el equipo.
- Nueva oferta: estimación de jornadas para un cliente. Dolor: reutilizar estimaciones de proyectos anteriores.

STACK: plataforma de datos de tu empresa, SQL, Python, TypeScript, herramientas de IA que uses a diario.

DOLORES (en orden):
1. Incorporar a gente nueva a un repositorio sin repetir explicaciones.
2. Documentar tras cada sesión sin perder decisiones.
3. Montar el informe de estado semanal.
4. Estimar jornadas con criterio.
5. Seguir dedicaciones contra lo vendido.

RESTRICCIONES: nada de datos de cliente fuera del entorno corporativo; Windows corporativo sin GPU; solo herramientas con licencia clara para uso profesional.

INTERESES DE APRENDIZAJE: LLM engineering (API, agentes, RAG, evals) programando.

SITUACIONES CON IMPACTO (para myday; sin días ni horas; no repitas la misma): incorporar a un desarrollador al repositorio, preparar el comité y su acta, el informe de estado semanal, estimar jornadas para una oferta, validar lo que construye un agente de código, documentar una base de datos, tus horas de estudio.

No hables de objetivos de carrera ni de cambios de rol en ningún texto.
